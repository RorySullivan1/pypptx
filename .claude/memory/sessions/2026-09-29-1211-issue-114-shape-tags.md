## What happened
- Asked first for "epic 238": no such issue (404; highest number is #117). Goal reset to #114.
- `p:custDataLst` (`CT_CustomerDataList`) and `p:tags` (`CT_TagsData`) element classes in
  `oxml/tags.py`; `CustDataLstOwnerMixin` gives `p:nvPr` and `p:cSld` `tags_rId`,
  `set_tags_rId()`, `remove_tags_rId()`. `p:nvGrpSpPr` gained its `nvPr` child accessor.

  RT.TAGS relationship and wrote no reference — with shape tags also on the slide part that
  would raise (several rels) or grab a shape's part. Legacy decks: an RT.TAGS rel no shape refers
  to is adopted (and the cSld reference written).
- Shape tags follow the shape: `duplicate_shape` copies each (group children too) via
  `TagsPart.copy()`; `remove_shape` drops the rel; slide `duplicate`/`import_slide` copy shape
  tags (`_PartCopier.copy(dedup=False)` for import, so identical tags don't share a part) and
  remove the slide-level reference they don't carry (it used to be left dangling).
- Tests: `tests/oxml/test_tags.py`, tag classes in test_base/test_shapetree/parts test_slide/
  parts test_presentation, 2 round trips; fixture builder `tests/unitutil/shapetags.py` injects
  PowerPoint-shaped tagged shapes, a tagged group child and slide tags. 3693 passed.
- `examples/comments_and_metadata.py` now demonstrates and asserts shape tags.

## Gotchas & dead ends
- cxml `xml()` declares only the namespaces it uses, so an element that gains an `r:id` via the
  API serializes with an extra `xmlns:r` vs the expected cxml: compare structure, or strip decls.
- Reading `.tags` on an untagged shape (or slide) creates an empty tags part — scanning every
  shape for a tag leaves empty parts behind. Matches `Slide.tags`; a `has_tags` could fix it.
