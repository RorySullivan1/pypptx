# Performance

Measurement notes and plan for issue #51 and the `v0.5.0` milestone
(`.meta/roadmap/stages/03-hardening-and-gaps/v0.5.0.md`). The harness lives in `tests/perf/`;
the "Baseline" section at the end of this file is regenerated by
`python -m tests.perf.run_baseline`.

## Scope

The v0.5.0 card sets the boundaries this work honors:

- **No native (C-extension) optimization.** Pure Python only; `lxml` is already C-backed.
- **No library-level multi-threading or async save.** `lxml` trees and the OPC package are not
  thread-safe; concurrency belongs in user code (see `examples/batch_process.py`).

## Done so far

- **Compiled-XPath and `qn()` caches** (PR #107). `BaseOxmlElement.xpath()` evaluates a
  compiled `etree.XPath` from `xmlchemy.compiled_xpath()` (cached per thread, bounded at 512
  entries); `ns.qn()` is `functools.lru_cache`d. On a 100-slide, 2,500-text-box deck the
  open → read-all-runs → edit → save job went from ~658 ms to ~400 ms (-39%).
- **Process fan-out recipe** (PR #108): `examples/batch_process.py`. 16 such decks: 10.6 s in a
  plain loop, 3.2 s with 4 worker processes, 2.0 s with 4 processes after the caches.

## What already exists (verify, do not reimplement)

- **Shape name / ID indexes** — `_BaseShapes._get_name_index` / `_get_id_index`
  (`src/pptx/shapes/shapetree.py`): built lazily on first lookup, dict-cached, invalidated on
  mutation. `bench_lookup.py` checks lookups stay flat across 10 / 100 / 1000 shapes.
- **Lazy part loading** — `_ZipPkgReader` (`src/pptx/opc/serialized.py`) reads each part's
  bytes on demand; `LazyXmlPart` (`src/pptx/opc/package.py`) defers parsing for parts usually
  left untouched (presProps, tableStyles, diagram and chartex parts).

## Findings from the #51 exploration

Measured on a synthetic text-heavy deck (CPython 3.11, 4 cores):

- **Time goes to pypptx's own Python**, not to C: cProfile put ~86% of the job in `pptx/`
  code before the caches (~81% after). cProfile over-weights Python calls, but the lever is the
  pure-Python layer — the opposite of #51's original "75–80% already in C" premise.
- **`__slots__` on proxies is not viable as written.** `@lazyproperty` (199 uses) caches in the
  instance `__dict__`; proxy construction is also only ~2% of the job.
- **A `compression` option on `save()` is low value.** zlib is ~9 ms of a ~50 ms save.
- **Cython is not justified** by these numbers, and the v0.5.0 card excludes native code.

## Remaining candidates for v0.5.0

- `TextFrame.paragraphs` and `_Paragraph.runs` (`src/pptx/text/text.py`) are plain properties
  that rebuild a tuple of proxies on each access; the `iter1x` vs `iter10x` columns below
  isolate that cost. Caching them needs invalidation on `add_paragraph` / `add_run` / text
  assignment.
- `_BaseShapes.__getitem__` / `__iter__` / `__len__` rebuild `list(_iter_member_elms())` per
  call.
- Child-element accessors (`xmlchemy` `get_child_element` / `get_child_element_list`) now
  lead the profile at ~3 µs a call, close to lxml's own floor.
- Benchmark against the v0.3.0 real-world corpus once it exists — image-heavy decks weight
  open and save, which the caches barely moved.

## Harness

- `tests/perf/corpus.py` — synthetic deck generator (slides, shapes/slide, paragraphs/shape,
  images); `SMALL`, `MEDIUM`, `LARGE` specs.
- `tests/perf/conftest.py` — session-scoped `synth_small` / `synth_medium` / `synth_large`.
- `tests/perf/bench_open.py`, `bench_iterate.py`, `bench_save.py`, `bench_lookup.py` — opt-in
  `@pytest.mark.perf` benchmarks with generous ceilings (smoke checks, not regression gates).
- `tests/perf/run_baseline.py` — writes `tests/perf/baseline.json` and replaces the Baseline
  section below: wall-clock, `tracemalloc` memory, cProfile top 20.
- `pyproject.toml` registers the `perf` marker and adds `-m 'not perf'` to `addopts`, so a
  plain `pytest` skips the benchmarks.

## Reproducing

```
pytest -m perf                       # opt-in benchmark run
python -m tests.perf.run_baseline    # refresh baseline.json and the section below
```
