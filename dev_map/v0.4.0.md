# v0.4.0 — Transitions, Animations (Read), Custom Layouts

**Branch:** `v0.4.0`
**Previous:** `v0.3.0`
**Status:** Planned

## Objective

Close the remaining MANIFEST-level feature gaps that don't require a rendering
engine: read-only access to slide transitions and animation timelines, plus
the ability to author new slide layouts on a slide master.

## Enhancements / Fixes

- Read-only `Slide.transition` property — surface `p:transition` element
  (type, duration, advance-on-click, advance-after-time).
- Read-only `Slide.timing` / `Slide.animations` view — enumerate the
  high-level timing tree (`p:timing` → `p:tnLst` → child time nodes); expose
  animation type, target shape, trigger, and duration without re-authoring.
- `SlideMaster.add_slide_layout(name)` — create a new layout part, link it
  via the master's `sldLayoutIdLst`, and register the relationship.
- `SlideLayout.add_placeholder(idx, type, ...)` — define placeholder
  positions and types on a custom layout.
- Layout cloning helper — duplicate an existing layout as a starting point
  for a new one.
- Handout master access (read-only) — register `HandoutMasterPart` content
  type and expose via `Presentation.handout_master` if present.

## Dependencies

- `v0.3.0` real-world corpus — needed to verify transition / timing parsing
  against actual decks; many real files use these elements.

## Out of Scope for this Version

- **Authoring** animations / transitions. Read-only only. Writing animations
  requires deeper schema work and is deferred past v1.0.
- Slideshow / preview rendering (out of project scope per `MANIFEST.md`).
- Theme color-scheme deep editing — that lands in `v0.5.0` or later if
  needed.

## Test Plan

- Unit tests for new OXML element classes (`CT_SlideTransition`,
  `CT_TimeNodeList`, etc.) using `cxml.element(...)` fixtures.
- Read-only API tests against corpus files from `v0.3.0` that contain
  transitions and animations.
- Round-trip: open a file with transitions, save without touching them,
  confirm bit-identical (or schema-equivalent) output.
- Authoring: create a new layout end-to-end in an example script and verify
  it shows up correctly in PowerPoint / LibreOffice.
- Type-check pass on the new public API surface.
