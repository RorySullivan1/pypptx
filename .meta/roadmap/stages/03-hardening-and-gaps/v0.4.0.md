## Objective
Harden the library against real-world `.pptx` files. The current test corpus is
mostly synthetic (cxml-built fixtures, the bundled default template and six small
files in `tests/test_files/`). This milestone brings in a corpus of
Microsoft-PowerPoint-authored files, drives round-trip tests through them, and fixes
the edge cases that surface. It also makes a damaged file fail with a clear exception
and puts the exception types callers see on a consistent footing.

## As built (2026-09-30)
What the implementation did differently from the plan below, or in addition to it:

- **Read-path `NotImplementedError` audit (step 4):** nothing else is reachable from a valid
  file. The dml ones are abstract stubs; the chart writer ones are authoring-only;
  `PlotTypeInspector` and `SeriesFactory` cover all 16 schema plot types; the only shape
  classes without their own `shape_type` are abstract bases.
- **Error messages (step 6):** existing wording is kept. The single
  `{what} must be {expected}, got {actual!r}` format was **not** adopted, because callers
  may match on message text and the audit's aim was compatible types. Where a domain class
  fits better than the generic one, the raise uses it: `ShapeRange`, placeholder-only and
  freeform-only access raise `ShapeError`; data-label leader lines and xlsx column refs raise
  `ChartError`. Left bare: `xmlchemy.py`'s internal pretty-print helper, `enum/base.py`
  (3 sites), `opc/packuri.py` (1) and `opc/package.py` (3).
- **Scope beyond the card** (accepted: the owner merged PR #122 with all four on 2026-10-01):
  - pytest now also collects `and_it_*` / `but_it_*` functions. 59 tests had never run, and 5
    of them exposed the next point.
  - `ShapeError`, `SlideError`, `ChartError` and `TableError` now also subclass `ValueError`,
    so callers catching `ValueError` (which these paths raised earlier) keep working.
  - A fourth new public name, `UnsupportedEffectError(ShapeError, NotImplementedError,
    AttributeError)`, for effects a shape has nowhere to hold. It keeps the old
    `NotImplementedError` / `AttributeError` behaviour, so `hasattr()` stays False.
  - Glow, reflection, soft edge and 3D on groups and graphic frames (these crashed with
    `AttributeError`), not only `GraphicFrame.shadow`.
- **Found by the stricter fidelity test:** internal hyperlink relationships with a fragment
  target (`#_ftn1`) were dropped on load. They are now kept, written back as internal, and
  stay internal when copied by slide duplication.
- **Found by Hypothesis:** bool accepted where an int is required (written as "True"),
  NaN/inf, `ST_Angle` overflow, `ST_PositiveFixedAngle` writing 21600000, and
  `ST_UniversalMeasure` raising `KeyError`. `--hypothesis-show-statistics` prints nothing for
  a `@given` nested in a parametrized test, so the budget was measured with a counter: 200
  examples for each of the 59 writable types.
- **Test-only corpus:** `MANIFEST.in` prunes it from the sdist (setuptools-scm would otherwise
  ship every tracked file). The corpus tests skip when the directory is absent.
- **Follow-up, not in scope:** a valid zip with malformed XML in a part still raises lxml's
  `XMLSyntaxError` rather than a pypptx exception.

## Evidence (pilot run, 2026-09-30)
This card was expanded after a pilot over the 85 `.pptx` files in Apache POI's
`test-data/slideshow` (fetched to a scratch dir, not committed). What it showed:

- **Round-trip holds on real files.** All 77 well-formed files opened, took a deep read
  walk (masters, layouts, slides, notes, groups, placeholders, text runs, tables, charts,
  fills), took one edit, saved and reopened. 73 of the 77 were saved by Microsoft
  PowerPoint (Windows or Mac); one by LibreOffice.
- **Nothing is dropped on save.** On a plain open-and-save, every XML part is unchanged
  apart from insignificant whitespace, except `[Content_Types].xml`, which pypptx
  regenerates. Every original part is still present, and its content type is kept or,
  where the original declared none, added. The original goal "catch and report unsupported
  elements rather than silently dropping them on save" therefore has no defect behind it.
  It becomes a fidelity **test** that keeps this true.
- **One read path raises.** `Shape.shape_type` raises `NotImplementedError("Shape instance
  of unrecognized shape type")` for a `p:sp` with no geometry. The case seen is a
  slide-number shape on a layout whose `p:ph` PowerPoint had stripped. (The pilot also
  reported `shape.fill` failing there. That was the pilot script, which read `fill` only after
  `shape_type`; `fill` itself reads fine.)
- **Damaged files fail badly.** Eight files are not valid zips (seven fuzzer-minimized
  crashers plus one truncated deck):
  - A file that exists but isn't a valid zip raises `PackageNotFoundError("Package not
    found at …")`, which misstates the problem.
  - Other damaged files leak a raw `zipfile.BadZipFile`.
  - `_ZipPkgReader.__del__` prints `AttributeError: … no attribute '_zipf'` to stderr
    whenever `zipfile.ZipFile()` raised inside `__init__`.
- **Exceptions.** 10 bare `ValueError` / `TypeError` raises remain in the API layer
  (`presentation.py`, `slide.py`, `shapes/range.py`, `text/text.py`,
  `chart/datalabel.py`, `chart/xlsx.py`, `dml/line.py`, `dml/color.py`). Another 35 are
  in `oxml/`; 16 of those are in `oxml/simpletypes.py` and reach callers through property
  setters. No class in `pptx/exc.py` subclasses `ValueError` or `TypeError`, so swapping
  raises to them outright would break `except ValueError:` callers.
- **Coverage today:** 93% (18,833 statements, 1,325 missed) at the v0.3.2 ship. The card's
  original "no decrease vs. v0.2.0" has no recorded v0.2.0 number, so today's figure is the
  floor.

- **Corpus licence:** committing the Apache 2.0 POI files is fine, **for testing only**.
  They live under `tests/test_files/real_world/`, which never reaches the wheel, and must

## Goals
1. **Real-world corpus** in `tests/test_files/real_world/`: 20–25 PowerPoint-authored
   files, plus a small `malformed/` set, with provenance and licence recorded.
2. **Corpus round-trip test**: every file opens, reads deeply, takes one well-defined
   edit, saves, reopens with the edit intact, and loses no part or XML content.
3. **Damaged input fails clearly**: an explicit, catchable exception that names the
   problem; no leaked `BadZipFile`; no stderr noise from the reader's `__del__`.
4. **Read paths never raise on valid files**: fix `Shape.shape_type` (and `fill`) for a
   geometry-less `p:sp`.
5. **`GraphicFrame.shadow`**: implement it for the graphic frames that have an effect list
   (tables, charts). Others raise a precise, documented error instead of the blanket
   `NotImplementedError`.
6. **Exception audit**: replace the bare `ValueError` / `TypeError` raises reachable from
   the API with `pptx.exc` types that still satisfy `except ValueError` / `except
   TypeError`. Use one message format: `{what} must be {expected}, got {actual!r}`.
7. **Hypothesis tests** for the `oxml/simpletypes.py` converters.

## Implementation plan
Ordered so each step lands on its own and later steps reuse earlier fixtures.

### 1. Corpus (`tests/test_files/real_world/`)
- **Source**: Apache POI `test-data/slideshow` (Apache License 2.0). Pin one SVN revision.
  Only take POI's own bug-reproduction and sample files. **Exclude** the decks scraped from
  public websites (file names beginning with a domain, e.g. `aascu.org_…`, `ca.ubc.cs…`,
  `rain.pptx`) and the large third-party-looking decks (`alterman_security`, `aptia`,
  `2411-Performance_Up`, `KEY02`, `customGeo`, `tika-2605`). Their content belongs to third
  parties, and redistributing it is doubtful even though POI ships them.
- **Proposed set** (~24 files, ~1.4 MB; sizes from the pilot):

  | Area | Files |
  |---|---|
  | Charts | `bar-chart`, `line-chart`, `pie-chart`, `radar-chart`, `scatter-chart`, `chart-slide-bg` |
  | SmartArt | `SmartArt`, `smartart-simple` |
  | Tables, i18n | `table-with-theme`, `table_test2`, `with_japanese` |
  | Comments | `45545_Comment` |
  | Media | `EmbeddedAudio`, `bug65523` |
  | Groups, pictures | `54542_cropped_bitmap`, `sample_pptx_grouping_issues`, `missing-blip-fill` |
  | Masters, layouts, backgrounds | `backgrounds`, `layouts`, `WithMaster`, `bug58144-headers-footers-2007` |
  | Transitions, animation (useful again in v0.5.0) | `bug60715`, `prProps` |
  | Non-PowerPoint author | `bug60993` (LibreOffice) |

- **`malformed/`**: 3–4 of the smallest `clusterfuzz-testcase-minimized-*.pptx`, plus a
  truncated zip and a non-zip file generated in the test rather than committed.
- **Provenance**: `tests/test_files/real_world/SOURCES.md` lists, per file, the upstream path,
  SVN revision, SHA-256, size, authoring application (from `docProps/app.xml`) and the
  features it exercises. Add `NOTICE` carrying POI's attribution and a copy of the Apache 2.0
  licence text. `.gitattributes` already marks `*.pptx` binary.
- **Owner check before committing binaries**: that Apache 2.0 test data in `tests/` is
  acceptable for this repository's licence and distribution. It is test-only: packages
  are found under `src/` only, so `tests/` never reaches the wheel.

### 2. Round-trip test (`tests/test_real_world_roundtrip.py`)
- Parametrize over `real_world/*.pptx`, with the file name as the test id. Mark the class
  `realworld` so it can be run alone.
- Per file:
  - Open the file.
  - Deep read walk: the pilot's walker (`tests/unitutil/deckwalk.py`) covers masters →
    layouts → slides → notes, recursing groups. It reads geometry, `shape_type`,
    placeholder format, text runs and font basics, table cells, chart type, categories and
    series values, and fill type. Any exception fails the test, naming the shape path.
  - One edit: add a textbox with known text to slide 1.
  - Save to `BytesIO`, then reopen.
  - Assert slide count, that the textbox and its text survived, and that the set of parts
    is a superset of the original.
- **Fidelity test (unedited)**: open, then save. For every XML part except
  `[Content_Types].xml`, the canonical XML parsed with `remove_blank_text=True` must equal
  the original. Content types: every original part keeps its type, or gains one where the
  original declared none. This replaces the original "catch unsupported elements" goal.

### 3. Damaged input (`src/pptx/opc/serialized.py`, `src/pptx/exc.py`)
- `_PhysPkgReader.factory`:
  - A missing path keeps raising `PackageNotFoundError`.
  - An existing file or stream that is not a valid zip raises a new
    `InvalidPackageError(PackageError)` naming the file and the reason (not a zip,
    truncated, bad central directory).
  - Wrap `zipfile.BadZipFile` and `zlib.error` raised while reading members the same way.
  - A zip without `[Content_Types].xml` or a package relationship gets the same treatment.
- `_ZipPkgReader.__del__`: guard with `getattr(self, "_zipf", None)`. Consider explicit
  `close()` and context-manager support later; that is new API, so it is out of scope.
- Tests: the `malformed/` files and the generated cases each raise `InvalidPackageError`,
  or `PackageNotFoundError` for a missing path. Use pytest's `unraisableexception` capture
  to assert that nothing reaches stderr.
- `InvalidPackageError` is the one new public name this version adds. It subclasses
  `PackageError`, so existing handlers still catch it. Record it in `exc.py`'s docstring
  and the docs' utilities page.

### 4. `Shape.shape_type` for a geometry-less `p:sp` (`src/pptx/shapes/autoshape.py`)
- **Decision needed**: return `MSO_SHAPE_TYPE.AUTO_SHAPE` (what the shape renders as: a
  rectangle-bounded text container), or `None` (unknown). **Recommend `AUTO_SHAPE`**: it
  keeps the return type non-optional. Needs a cxml unit test for the
  exact element seen, `p:sp` with `p:spPr` empty, no geometry, not `txBox`, with a
  `txBody`.
- Audit the other `NotImplementedError` raises on read paths
  (`grep -rn "raise NotImplementedError" src/pptx/{shapes,text,chart,dml}`) and list any
  that valid files can reach.

### 5. `GraphicFrame.shadow` (`src/pptx/shapes/graphfrm.py`, `src/pptx/oxml/table.py`)
- Table: a `ShadowFormat` over `a:tbl/a:tblPr`. `CT_TableProperties` needs its
  `EG_EffectProperties` children (`a:effectLst` / `a:effectDag`) declared, bottom-up per
  the types-first rule.
- Chart: a `ShadowFormat` over the chart part's `c:chartSpace/c:spPr`. This belongs to the
  chart part, not the frame, so reach it through `GraphicFrame.chart`.
- Anything else (OLE object, SmartArt, media): raise `ShapeError("shadow is not supported
  for a graphic frame containing <kind>")` rather than `NotImplementedError`.
- Tests: unit tests per kind, plus a round-trip test that a table shadow and a chart shadow
  survive save and reload. The rendering check is human-gated (see acceptance).

### 6. Exception audit (`src/pptx/exc.py` + the 10 API sites + `oxml/simpletypes.py`)
- **Compatibility decision**: add
  `class InvalidValueError(PyPptxError, ValueError)` and
  `class InvalidTypeError(PyPptxError, TypeError)`. Raise these where a bare `ValueError` /
  `TypeError` is raised today, so `except ValueError`, `except TypeError` and
  `except PyPptxError` all keep working.
- Scope:
  - the 10 API-layer sites listed under Evidence;
  - the `simpletypes.py` validators (`validate_int_in_range`, `validate_string`, …), which
    back every property setter.
  - Leave the internal `oxml/` parse-time raises that callers never see as they are, and
    list them in the PR.
- Message format: `{what} must be {expected}, got {actual!r}`, e.g. `"rot_x must be an int
  in range -90..90, got 120"`.
- Tests: the existing tests asserting `ValueError` / `TypeError` must pass unchanged, which
  is the proof of compatibility. Add a test per new class asserting `isinstance` of both
  bases.

### 7. Hypothesis (`tests/oxml/test_simpletypes_properties.py`)
- Add `hypothesis>=6` to the `dev` extra.
- Properties, per converter class:
  - `convert_from_xml(convert_to_xml(v)) == v` over each type's valid domain (ints in range,
    percentages, angles, EMU, hex colors, booleans);
  - `validate` rejects values outside the domain with `InvalidValueError` /
    `InvalidTypeError` (after step 6);
  - `convert_from_xml` on arbitrary strings either returns a value or raises one of the
    documented exceptions, and never anything else.
- Keep the example budget small enough for CI (`max_examples=200`, `derandomize=True` so
  runs are reproducible). Run once with `--hypothesis-show-statistics` for the acceptance
  evidence.

## Dependencies
- v0.3.2 shipped (docs build), so the new exception classes land on the docs' utilities
  page and `-W` checks their docstrings.
- **Owner:** the licence check in step 1 before the corpus binaries are committed.

## Out of scope
- New public API beyond `InvalidPackageError`, `InvalidValueError`, `InvalidTypeError` and
  making `GraphicFrame.shadow` work. Not included: a `close()` or context manager on
  `Presentation`, `has_tags`, `Chart.series_axis`.
- Performance work. That is v0.6.0, even if profiling falls out of corpus debugging.
- Authoring transitions or animations. Read-only access is v0.5.0; the corpus's
  transition and animation files will serve it.
- The 2D chart writers' negative `c:axId` values (schema-invalid, tolerated by
  PowerPoint). They are noted in the #115 session log; fix them only if a corpus round-trip
  exposes a problem.

## Objectives / acceptance
- `tests/test_real_world_roundtrip.py` runs over every corpus file, and each one opens,
  reads deeply, edits, saves and reopens without raising. The fidelity test passes on
  every file.
- Every `malformed/` input and generated damaged input raises `InvalidPackageError` (or
  `PackageNotFoundError` for a missing path), and nothing is printed to stderr.
- No read path in the round-trip walk raises on a corpus file; the geometry-less `p:sp`
  unit test passes.
- `GraphicFrame.shadow` works for tables and charts, with round-trip tests. Other kinds
  raise `ShapeError`.
- No bare `ValueError` / `TypeError` raise is left at the audited sites. The existing tests
  for those exceptions pass unchanged.
- The Hypothesis tests pass. `--hypothesis-show-statistics` shows each property ran its full
  example budget.
- `pytest --cov=pptx` is at least 93% (the v0.3.2 floor). `sphinx-build -W` is still clean.
- **Human-gated:** open three round-tripped corpus files, including one with a chart and
  one with SmartArt, in PowerPoint, and confirm they open without a repair prompt and look
  unchanged. Also confirm a table shadow and a chart shadow set through the API render.
