## Objective
Make `pypptx` viable for production workloads at scale — large decks (200+
slides), shape-heavy slides (1000+ shapes), bulk reporting workflows. Profile,
optimize hot paths, and add ergonomic helpers that reduce boilerplate.

## Dependencies
- `v0.4.0` real-world corpus — needed to benchmark against real-world file
  characteristics, not just synthetic fixtures.

## Out of scope
- Multi-threaded / async save. The OPC zip format and `lxml` element trees
  are not thread-safe; concurrency belongs to user code, not library code.
- New feature surface — performance pass only. If a missing API is required
  to make a benchmark realistic, file it for `v0.7.0`.
- Native (C-extension) optimizations. Pure Python only; `lxml` is already
  C-backed.

## Objectives / acceptance
- Baseline benchmark numbers captured at branch open and re-run at branch
  close — regression gate is "no slower than baseline on any tracked op".
- All existing tests pass — caching changes must not break invalidation.
- New `tests/perf/` reports under 60 s wall-clock on CI hardware.
- Memory footprint for the lazy-blob path measured with `tracemalloc` and
  documented in the milestone summary.
