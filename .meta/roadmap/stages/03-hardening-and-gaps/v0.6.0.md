## Objective
Solve the most-requested ergonomic gap in text editing: find / replace
operations that work correctly across XML run boundaries. PowerPoint splits a
single visual word across multiple `<a:r>` runs to preserve fine-grained
formatting; naive string operations break this. Provide reliable helpers that
preserve run formatting where possible and gracefully degrade where not.

## Goals
- `TextFrame.replace(old, new, *, count=None, regex=False)` — find/replace
  across runs in document order. When the match falls within a single run,
  preserve all formatting. When it spans runs, the new text inherits the
  formatting of the first matched run.
- `TextFrame.find_all(pattern, *, regex=False)` — return iterable of
  `TextMatch` objects with `paragraph_index`, `start`, `end`, and the
  spanning runs.
- `Paragraph.replace(...)` and `Paragraph.find_all(...)` — same semantics at
  paragraph scope.
- `TextFrame.iter_runs()` / `TextFrame.iter_chars()` — low-level traversal
  helpers for users who need fine control.
- Helper for merging runs with identical formatting after a replace (reduces
  XML bloat).
- Document the limitation around `Lines()` (per `feature-manifest.md` — requires a
  rendering engine and stays out of scope).

## Dependencies
- `v0.5.0` lazy blob loading and caching audit — text traversal hits the
  same caches and we want the perf pass to stabilize first.

## Out of scope
- Visual line-break calculation. Documented in `feature-manifest.md` as inherently
  out of scope (requires rendering engine).
- Smart formatting reconciliation across spanning replacements (e.g.
  "preserve bold from middle run when replacing across three runs"). The
  documented behavior is "match first run's formatting"; smarter merging is
  future work.
- Word / sentence boundary navigation (`Words()`, `Sentences()` in VBA).
  Outside scope for v1.0; can revisit post-1.0.

## Objectives / acceptance
- Unit tests for replace covering: single-run match, multi-run match,
  no-match, empty-string corner case, regex mode on/off, count limit.
- Round-trip test: replace a known string in a corpus file, save, reopen,
  re-find — confirms idempotence.
- Property-based test: random insert/replace/find sequence ends with text
  that matches a Python-string-level expected value.
- No performance regression vs. `v0.5.0` baseline on the text-heavy
  benchmark.
