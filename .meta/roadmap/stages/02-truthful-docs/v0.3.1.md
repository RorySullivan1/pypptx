## Objective
Give downstream readers a runnable demonstration of every major feature area
that lacks one today. After v0.2.0 the documentation is accurate; this
milestone makes the surface *learnable* — every feature group named in the
manifest has at least one example script that writes a `.pptx`, re-opens it,
and asserts the round trip survived.

**Two findings that change the goals below:**

1. **Shape-level tags have no API.** `Slide.tags` exists; there is no equivalent on a shape.
   The XML slot is reserved in the element sequences (`p:custDataLst` in
   `src/pptx/oxml/shapes/shared.py:312`), so this is an unimplemented surface, not an
   unrepresentable one. **Filed as #114 for v0.4.0; not patched here** — the original card asked an
   example to demonstrate "slide and shape tags", which is not currently possible.
2. **`examples/comments_and_metadata.py` already covers sections, slide tags and typed custom
   properties.** A new `sections_tags_custom_props.py` would be a near-duplicate. What that
   script actually lacks is the round-trip assertion this version is about: it prints and
   saves, and never re-opens the file. That goal is rescoped accordingly (see Goals #6).

## Goals
1. **`examples/chart_trendlines_error_bars.py`** — a clustered-column chart with three series.
   Series 1 gets a linear trendline with `display_equation` and `display_r_squared`; series 2 a
   polynomial trendline (`order=2`) with `forward`/`backward` projection; series 3 a
   moving-average trendline (`period=2`). Error bars: fixed value on series 1, percentage on
   series 2, `XL_ERROR_BAR_TYPE.STD_DEV` on series 3, one of them with `has_end_cap = False`.
   *Asserts, after reopening:* trendline count per series, each `trendline_type`, the `order`
   and `period` values, and each series' error-bar `type`, `direction` and `value`.
2. **`examples/add_chart_secondary_axis.py`** (exists) — add the round-trip asserts only:
   reopen, confirm both plots survive, that the second plot is on the secondary axis, and that
   the value axes differ. No restructuring of the script.
3. **`examples/chart_3d_view.py`** — a 3D column chart: set `rot_x`, `rot_y`, `perspective`,
   `depth_percent`, `height_percent`, turn `right_angle_axes` off, then fill the floor, side
   wall and back wall and set a wall `thickness`.
   *Asserts:* every view-3D scalar reads back equal, and each of the three surfaces reports the
   fill colour it was given.
4. **`examples/custom_slide_master_walk.py`** — read-only. Walks master → layout → slide for a
   deck built from the default template, printing each placeholder's `idx`, `ph_type`, and
   `left/top/width/height` at all three levels, marking each value *inherited* or *overridden*.
   Then overrides one slide placeholder's position to show the resolution flip.
   *Asserts:* an untouched slide placeholder's dimensions equal its layout ancestor's; after
   the override, the slide value wins and the layout's is unchanged.
5. **`examples/picture_effects.py`** — one picture per effect: brightness, contrast, grayscale,
   `transparency_color`, and a crop. Image generated in-process with Pillow (already a hard
   dependency) so the script needs no asset file.
   *Asserts:* each property reads back its written value after reopening, and `is_grayscale`
   is `True` only on the intended picture.
6. **Round-trip asserts for `examples/comments_and_metadata.py`** (replaces the planned
   `sections_tags_custom_props.py`, which would duplicate it — see finding 2). Reopen the
   saved deck and assert: section names and their slide ids, `slide.tags` values, the three
   typed custom properties round-trip with their Python types intact (`str`, `int`, `bool`),
   and both comment kinds survive with their authors and the resolved flag.
7. **README "Examples" table** lists every script, and each new script's module docstring names
   the `.claude/context/feature-manifest.md` section it demonstrates.

## Out of scope
- **New public API.** The shape-tags gap from finding 1 is filed as #114 for v0.4.0, not fixed here.
- Docstring audit and Sphinx scaffold — `v0.3.2`.
- Changes to existing `examples/` scripts *other than* adding round-trip asserts to
  `add_chart_secondary_axis.py` (goal 2) and `comments_and_metadata.py` (goal 6). The original
  card forbade touching existing scripts at all while also asking for goal 2's asserts; this
  states the carve-out explicitly instead of leaving the contradiction in place.
- Rendering checks. Whether these decks *look* right in PowerPoint stays `human-gated`.

## Objectives / acceptance
- `python examples/<name>.py` exits 0 for every script from a clean working directory, and the
  file it writes re-opens via `Presentation(...)` without raising.
- Assertions are bare `assert`s against values read back from the reopened file — not against
  the in-memory objects that were just written.
- Each new assertion block has been seen to fail once (perturb an expected value, observe the
  `AssertionError`, restore). A check that cannot fail is not a check.
- `pytest -q` stays at 3657 passed; all 7 CI cells green.
- `ls examples/` and the README "Examples" table list the same files.
